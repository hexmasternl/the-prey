# The Prey — Local Development

Three things can run locally, independently:

| Part | Start from | What you get |
|---|---|---|
| Backend | `server/src/Aspire/ThePrey.Aspire.AppHost` (Aspire) | 4 APIs + gateway on `http://localhost:5000`, dashboard on `https://localhost:17247` |
| Android app | `app/src` (Gradle) | debug build on an emulator/device, against the **deployed** backend by default |
| Website | `website/src` (Hugo) | `http://localhost:1313/` |

For generic Aspire lifecycle problems (file locks, `MSB3491`/`CS2012`, port conflicts, hot reload, `aspire update`) use the `aspire-orchestration` skill; for logs and traces use `aspire-monitoring`. This skill covers what is specific to this repo. When the built-in `run` skill asks how to launch this project, use the commands below.

## Prerequisites

| Tool | Why | Check |
|---|---|---|
| .NET SDK 10 | APIs and AppHost (`net10.0`) | `dotnet --version` |
| Aspire CLI 13.x | `aspire start/stop/ps/wait/logs`; AppHost SDK is `Aspire.AppHost.Sdk/13.4.3` | `aspire --version` |
| Docker Desktop (running) | Postgres, RabbitMQ, Azurite and the YARP gateway run as containers | `docker ps` |
| Dapr CLI, initialised | Every API runs with a Dapr sidecar (`WithDaprSidecar`) | `dapr --version`; `dapr init` once (creates `dapr_placement`, `dapr_scheduler`, `dapr_redis`, `dapr_zipkin`) |
| JDK 17+ and Android SDK | app build (`compileSdk 37`, `minSdk 26`) | `java -version`; `app/src/local.properties` has `sdk.dir` |
| Hugo extended | website | `hugo version` |

**AppHost user secrets** (id `ce25ccc8-abfe-44a3-b135-276e9e176652`): `Parameters:rabbitmq-username`, `Parameters:rabbitmq-password` (declared as secret parameters in `AppHost.cs`) and `Parameters:postgres-password` (generated by Aspire on first run). Set the RabbitMQ pair once:

```powershell
dotnet user-secrets set "Parameters:rabbitmq-username" "<user>" --project server/src/Aspire/ThePrey.Aspire.AppHost
dotnet user-secrets set "Parameters:rabbitmq-password" "<password>" --project server/src/Aspire/ThePrey.Aspire.AppHost
```

Without them `aspire run` asks in the dashboard and `aspire start --non-interactive` cannot finish.

## Backend: start, check, stop

`server/src/Aspire/aspire.config.json` points the CLI at the AppHost, so run from `server/src/Aspire`, or pass `--apphost` from anywhere:

```powershell
$A = "server/src/Aspire/ThePrey.Aspire.AppHost/ThePrey.Aspire.AppHost.csproj"
aspire start --apphost $A                     # background; prints the dashboard login URL
aspire wait gateway --status up --apphost $A
aspire wait hexmaster-theprey-games-api --status up --apphost $A
aspire describe --apphost $A                  # resource table: state, health, URLs
aspire stop --apphost $A
```

`aspire run --apphost $A` runs in the foreground instead (Ctrl+C stops it). `.mcp.json` registers the Aspire MCP server (`aspire agent mcp`), so with an AppHost running you can also use the `mcp__aspire__*` tools (`list_resources`, `list_console_logs`, `list_traces`, `execute_resource_command`).

### What runs, and where

| Resource (`AspireConstants.Resources`) | Kind | Local address |
|---|---|---|
| `gateway` | YARP container | **`http://localhost:5000`** (fixed) — routes `/users/**`, `/playfields/**`, `/games/**`, `/notifications/**` |
| `hexmaster-theprey-users-api` | project + Dapr | `https://localhost:7069`, `http://localhost:5015` |
| `hexmaster-theprey-playfields-api` | project + Dapr | `https://localhost:7197`, `http://localhost:5176` |
| `hexmaster-theprey-games-api` | project + Dapr (statestore, pubsub) | dynamic port, see `aspire describe` |
| `hexmaster-theprey-notifications-api` | project + Dapr (pubsub) | dynamic port |
| `postgres` / database `games` | container | dynamic port; Games applies EF migrations at start-up |
| `messaging` | RabbitMQ container, backs Dapr `pubsub` | `5672` (fixed), management UI `http://localhost:15672` |
| `storage` (`users-tables`, `playfields-tables`) | Azurite container, **persistent** lifetime | dynamic ports; data survives restarts |
| `statestore` | Dapr state store | in-memory locally |
| Dashboard | AppHost | `https://localhost:17247` (profile `https` in `Properties/launchSettings.json`) |

In Development every API maps OpenAPI and Scalar (`/openapi/v1.json`, `/scalar`) on its own URL, not through the gateway.

### Smoke test

```powershell
curl.exe -s -o NUL -w "%{http_code}\n" http://localhost:5000/games/active    # 401 = gateway, API and auth are up
curl.exe -s -o NUL -w "%{http_code}\n" http://localhost:5000/playfields      # 401
```

A `502`/connection refused means the target API is not up yet: check `aspire describe` and `aspire logs <resource> --apphost $A`.

## Authentication against a local backend

There is no local identity provider. `AddDefaultAuthentication` (in `ThePrey.Aspire.ServiceDefaults/Extensions.cs`) validates real Auth0 tokens: authority `https://theprey.eu.auth0.com/`, audience `https://api.theprey.nl`, overridable with `Auth0:Domain` / `Auth0:Audience`. So the same login works locally and in the cloud, and the caller is the token's `sub`.

- Easiest token source: sign in with the debug app pointed at the local gateway (below). The Users API creates the profile on first call.
- Don't paste tokens or client secrets into files, commits or logs.

## Local configuration gaps (know before you test)

- **Web PubSub has no emulator.** The AppHost has the Web PubSub resource commented out, while the Games and Notifications APIs register `AddAzureWebPubSubServiceClient("webpubsub")`. Locally nothing supplies `ConnectionStrings:webpubsub`, so the notifications-token endpoint and pushes can't work. Lobby/game screens then only update from HTTP snapshots (the app's game-state service resyncs every 3 minutes). To test realtime, give both services a real connection string (for example a local, uncommitted `builder.AddConnectionString("webpubsub")` + `.WithReference(...)` in `AppHost.cs` with the value in AppHost user secrets). See `the-prey-realtime-communication`.
- **No Azure App Configuration locally.** It is only used when `AppConfigurationHostname` is set, so cloud keys and feature flags are absent: `Games:MinimumAppVersion` is unset (the version check doesn't block) and the `EnableDailyGamesExport` flag is off. Set them for a test run with environment variables on the project (`Games__MinimumAppVersion`, `FeatureManagement__EnableDailyGamesExport`) via a local `.WithEnvironment(...)`, and don't commit it.

## Android app

Defaults in `app/src/app/build.gradle.kts` point at production: `apiBaseUrl` = the deployed Container Apps gateway, Auth0 tenant `theprey.eu.auth0.com`, `auth0Scheme=https`. Override any of them per build with `-P` (or `ORG_GRADLE_PROJECT_<name>`); they become `BuildConfig.API_BASE_URL` / `AUTH0_*`.

```powershell
# from app/src — against the deployed backend (the normal case)
./gradlew installDebug
```

**Against the local gateway:**

```powershell
./gradlew installDebug -PapiBaseUrl=http://10.0.2.2:5000/          # emulator: 10.0.2.2 is the host
adb reverse tcp:5000 tcp:5000; ./gradlew installDebug -PapiBaseUrl=http://localhost:5000/   # USB device
```

- Keep the trailing `/` (Retrofit base URL).
- **Cleartext is blocked.** `targetSdk` is 37 and the repo has no network security config, so plain `http://` calls fail with "CLEARTEXT communication … not permitted". For a local run, add a debug-only config that permits cleartext for `10.0.2.2` and `localhost` (`app/src/app/src/debug/res/xml/network_security_config.xml` and `app/src/app/src/debug/AndroidManifest.xml` with `android:networkSecurityConfig`). It isn't in the repo yet: either keep it local or propose it as its own change. Never allow cleartext in `main` or release.
- `-P` values aren't stored. Rebuild without the flag to go back to production. `findProperty` does not read `local.properties`; for a sticky override use `~/.gradle/gradle.properties`.
- **Auth0 sign-in on debug builds:** with `auth0Scheme=https` the callback `https://theprey.eu.auth0.com/android/nl.hexmaster.theprey/callback` only reaches the app when the debug key's SHA-256 is registered in Auth0 (Application → Advanced → Device Settings) and App Links verification has run. If the callback opens an Auth0 page instead of the app, run `adb shell pm set-app-links-user-selection --user cur --package nl.hexmaster.theprey true theprey.eu.auth0.com`. `-Pauth0Scheme=theprey` avoids App Links but needs that callback URL allowed in Auth0 first.
- Game invites: `adb shell am start -a android.intent.action.VIEW -d https://theprey.nl/games/join/<guid>/1234 nl.hexmaster.theprey`.
- Location on the emulator: Extended controls → Location (or `adb emu geo fix <lon> <lat>`). Gameplay needs precise location and "Allow all the time" (see `the-prey-play-store`).

App conventions: `the-prey-android-feature`.

## Website

```powershell
cd website/src
hugo server            # http://localhost:1313/ → /en/ and /nl/; live reload
hugo                   # production build into website/src/public (what CI deploys)
```

`/games/join/...` is a static page (`static/games/join/index.html`) that Azure Static Web Apps rewrites (`static/staticwebapp.config.json`). `hugo server` doesn't apply those rewrites, so open `http://localhost:1313/games/join/index.html` directly. Content rules: `the-prey-website-content`, `the-prey-multilingual`.

## Known failure modes

| Symptom | Cause | Fix |
|---|---|---|
| Containers `gateway-*`, `postgres-*`, `messaging-*` still running after `aspire stop` (seen 90 s+ after stop); next start fails on port 5000 / 5672 / 15672 | Orphaned session containers holding the **fixed** ports | `docker ps`, then `docker rm -f <name>` for those three. Leave `storage-*` (persistent Azurite, your table data) and `dapr_*` alone |
| `Step 'azure-prepare-resources' failed: The endpoint 'http' is not allocated for the resource 'hexmaster-theprey-users-api-dapr-cli'` | Seen in the old `aspire-run.err.log` (June, `src\Aspire` path, before the move to `server/`): Azure role-assignment preparation read a Dapr sidecar endpoint too early | Doesn't happen with the current AppHost (SDK 13.4.6). If it returns after a package bump, check `Aspire.Hosting.*` and `CommunityToolkit.Aspire.Hosting.Dapr` versions together and any newly added Azure resource |
| Games logs `fail: … Failed executing DbCommand … FROM "__EFMigrationsHistory"` | First start on a fresh Postgres: the history table doesn't exist yet | Harmless; the next lines apply `InitialCreate` |
| `messaging` Unhealthy for ~30 s; Games/Notifications stay `Waiting` | RabbitMQ boot; both `WaitFor(rabbitmq)` | Wait (`aspire wait hexmaster-theprey-games-api --status up`) |
| Sidecars `*-dapr-cli` fail to start | Dapr not initialised, or Docker not running | `dapr init`; start Docker Desktop |
| Parameter prompt / start hangs | RabbitMQ user secrets missing | Set them (Prerequisites) |
| Build errors about locked DLLs while running | AppHost holds the binaries | `aspire stop` first, or see `aspire-orchestration` |
| Realtime never arrives locally | No Web PubSub connection string | See *Local configuration gaps* |
| App: "No connection" against local backend | Cleartext blocked, wrong host (`localhost` on the emulator), or missing `adb reverse` | See *Android app* |

The `aspire-run.out.log` / `aspire-run.err.log` files at the repo root are stale output from that June run. `*.log` is gitignored, so they're safe to delete.

## Checklist

- [ ] Docker running, `dapr init` done, RabbitMQ user secrets set.
- [ ] `aspire start --apphost …` then `aspire wait gateway` and `aspire wait hexmaster-theprey-games-api`.
- [ ] `http://localhost:5000/games/active` answers `401` without a token.
- [ ] App built with the right `-PapiBaseUrl` (trailing slash; debug-only cleartext config when using `http`).
- [ ] `hugo server` from `website/src` for site work.
- [ ] `aspire stop`, then check `docker ps` for orphaned `gateway-*` / `postgres-*` / `messaging-*` containers.
- [ ] No tokens, secrets or local-only AppHost/manifest tweaks committed.
