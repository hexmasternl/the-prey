# Proposal

## Why

The Kotlin app in `app/src` is the only client, but nothing in CI builds it or ships it to Google Play: the Ionic (`android-release.yml`) and MAUI (`maui-android-release.yml`, `maui-ios-release.yml`) workflows targeted clients that no longer exist and were dropped in `f9df432` without a replacement. Every app build is currently uploaded by hand, without a version from the shared version line and without store release notes in the two languages the app ships in.

## What Changes

- Confirm the Ionic and MAUI release workflows and their docs are gone and that no workflow, doc or secret reference to them remains (they were deleted in `f9df432`; this change owns the clean-up check).
- Add `.github/workflows/android-release.yml` for the Kotlin app:
  - version from the shared `version.yml` (GitVersion), `versionName` = `semVer`, `versionCode` derived from `major`/`minor`/`patch`;
  - lint + unit tests on pull requests and before every publish;
  - a signed release bundle (`bundleRelease`) published to the Play Console **internal testing track** for `nl.hexmaster.theprey` — a private release visible only to the internal testers list; promotion to other tracks stays a manual Play Console action;
  - release notes generated by GitHub Copilot from the app commits since the last successful app publish, in **English and Dutch**, sent to Play as the "What's new" text for both languages and used as the GitHub release body;
  - after a successful Play upload, the shared create-release action creates the `v<semVer>` tag and GitHub release.
- Extend the shared create-release action (planned in `workflow-centralized-versioning`) with an optional release-notes input, so a caller can supply its own notes instead of GitHub's generated ones.
- Narrow `workflow-centralized-versioning` so it no longer plans its own app workflow: its section 4, the app requirements in its spec delta and its app migration steps move to this change.

## Capabilities

### New Capabilities
- `android-app-release`: how CI verifies, versions, signs and publishes the Kotlin Android app to the Play Console internal track, how it produces bilingual (English + Dutch) release notes, and when it creates the GitHub release for the shipped version.

## Impact

- **Files:** new `.github/workflows/android-release.yml`; `.github/actions/create-release/action.yml` (optional `notes-file` input); `openspec/changes/workflow-centralized-versioning/{proposal,design,tasks}.md` and its spec delta (app parts removed); `CLAUDE.md` (release section for the app).
- **Dependency:** the create-release action from `workflow-centralized-versioning` (its sections 1–3) must land first or together with this change.
- **Secrets:** `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS`, `PLAY_SERVICE_ACCOUNT_JSON` (signing + Play), `COPILOT_GITHUB_TOKEN` (fine-grained PAT with the Copilot Requests permission, for the release notes).
- **Play Console:** the service account needs release rights on `nl.hexmaster.theprey`; the internal testing track needs a testers list. `versionCode` must stay above the highest code already in Play.
- No app code, backend, API or infrastructure changes.
